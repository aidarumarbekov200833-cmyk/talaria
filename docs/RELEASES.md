# Релизы Talaria

Страница для владельца: что менялось, когда и почему — человеческим языком.
Технические подробности каждой правки — в коммитах и `CHANGELOG.md`.

## Как читать этот репозиторий

| Папка              | Что там                                                       |
| ------------------ | ------------------------------------------------------------- |
| `frontend/`        | Лендинг и кабинет: `index.html`, `css/` (слои), `js/` (модули) |
| `backend/`         | API на FastAPI, база PostgreSQL, 539 тестов                   |
| `tg-mini-client/`  | Вход через Telegram и шлюз переписки (MTProto)                |
| `deploy/`          | Прод-конфигурация, `.env.production` с живыми ключами          |
| `scripts/`         | Сборка релиза, бэкапы, проверки контрактов                    |
| `docs/`            | Документация, включая эту страницу                            |
| `.github/workflows/` | Автопроверки на каждый push                                 |

Прод: https://talaria.mooo.com · сервер: Azure VM, `docker compose --profile tls`.

Каждый релиз = один коммит. Смотреть историю: вкладка **Commits** на GitHub —
там дата, список файлов и описание, что именно поменялось.

## Проверки перед каждым релизом

Ни один релиз не уходит на прод, пока не зелёные:

- `backend`: `pytest` — 539 тестов;
- `frontend`: 56 юнит-тестов, 15 браузерных (Playwright), проверка форматирования;
- гейты контрактов: DOM (ни один класс из вёрстки не пропал) и Actions
  (каждая кнопка в HTML имеет живой обработчик в JS);
- после деплоя: `md5` изменённых файлов сверяются с живым сайтом + `/api/health`.

## Бэкапы (уже работают)

Сервис `backup` в `docker-compose.yml`: сжатый дамп базы и архив
Telegram-сессий, хранение `BACKUP_KEEP_DAYS` дней, старое удаляется само.
Сервис `backup-verify` раз в неделю разворачивает последний дамп в отдельную
временную базу и проверяет таблицы — чтобы не оказалось «архивы есть, а
восстановить нельзя». `backup-watchdog` шумит в Telegram, если копия не
появилась вовремя.
