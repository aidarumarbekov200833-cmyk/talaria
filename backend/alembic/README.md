# Миграции БД (Alembic)

«Источник правды» для схемы — модели SQLAlchemy в `app/models.py`. Alembic
настроен так, чтобы не дублировать ни URL базы, ни описание таблиц:

* URL берётся из `app.config.settings.database_url` (см. `env.py`), а не из
  `alembic.ini`. Меняете `.env` — меняется и то, куда ходит Alembic.
* `target_metadata = Base.metadata`, и `env.py` импортирует `app.models`, поэтому
  `--autogenerate` видит все таблицы.

## Как это уживается с `create_all`

`init_db()` при старте всё ещё вызывает `Base.metadata.create_all()`. Это
безопасно: `create_all` только **до**создаёт недостающие таблицы и никогда не
меняет существующие. То есть на чистой базе достаточно любого из двух путей, а на
рабочей — схему меняют только миграции.

Практика:

* **Новая, пустая база** — можно просто дать приложению подняться (create_all),
  затем зафиксировать состояние: `alembic stamp head`. Либо сразу
  `alembic upgrade head`.
* **Уже существующая база** (поднята прежними запусками через create_all) —
  один раз помечаем её базовой ревизией, не накатывая её заново:

  ```bash
  cd backend
  alembic stamp head
  ```

* **Изменили модели** — генерируем ревизию и применяем:

  ```bash
  cd backend
  alembic revision --autogenerate -m "что изменилось"
  alembic upgrade head
  ```

  Autogenerate — черновик: просмотрите файл в `alembic/versions/` перед тем, как
  катить. Он не всегда ловит переименования и серверные дефолты.

## Базовая ревизия

`versions/20260803_0001_baseline.py` создаёт всю текущую схему (15 таблиц) ровно
в том виде, в каком её описывают модели: имена индексов `ix_<table>_<column>`,
именованные уникальные ограничения `uq_*`, каскады `ON DELETE CASCADE`. Она
написана вручную (autogenerate требует живого подключения к базе), но выверена
против метаданных ORM.

Запускается из каталога `backend/` — там лежит `alembic.ini` с
`prepend_sys_path = .`, чтобы импортировался пакет `app`.
